# Tooldeck 1.4.0

Tooldeck 1.4 consolidates the desktop and plugin runtime while retaining the commands-only,
trusted local plugin workflow introduced in 1.3.

- Desktop now uses Nuxt CSR, Vue and TDesign, with domain-specific APIs behind the single
  preload bridge. CLI and Desktop main share the Node application service.
- The new `@tooldeck/json-schema@0.1.0` provides scoped Draft-07 engines, opaque validators
  and neutral validation diagnostics. Runtime, package handling and author tools share
  the same command input/output profiles.
- Private runtime/application services use Effect for lifecycle coordination and Effect
  Schema at selected internal boundaries. Public plugin contracts remain Effect-neutral.
- Built-in plugins are packaged and validated through `.tdplugin` before being staged
  into CLI and Desktop artifacts.
- The authoring stack targets Vite 8. New projects use the matching 1.4 protocol, SDK,
  plugin-tools and Vite integration packages. `@tooldeck/plugin-package` advances to 0.2.0.

Compatibility covers TPP v1 manifests and packages in the publicly supported Tooldeck 1.3
authoring profile. Runtime-only acceptance of unsupported input keywords such as `oneOf`,
`anyOf`, `$ref` and `$id` is outside that contract. See the
[plugin authoring guide](https://github.com/origin-coding/tooldeck/blob/v1.4.0/docs/plugin-authoring/README.md)
for current schema rules and supported workflows.

Plugin installation, lazy activation, structured command results, history, enable/disable,
uninstall and retained-data purge retain their existing ownership boundaries. This release
does not add marketplace, remote installation, signing, sandboxing or new contribution types.

Downloads include Windows NSIS/MSI installers, Linux AppImage and macOS DMG. See
[#42](https://github.com/origin-coding/tooldeck/issues/42) for release acceptance evidence
and actual platform smoke coverage.
